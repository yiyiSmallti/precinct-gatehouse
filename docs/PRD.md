# Gatehouse 首期 PRD

版本 0.1 · 对应架构文档 v0.18 · 范围：首期（MVP）

## 1. 目标

一个独立可用的模型网关：对内对外只说 OpenAI 兼容 HTTP，把路由、脱敏、计量、短时效令牌做成一个单二进制。个人用户把它当本机网关用；组织装上 `gatehouse-cloister` 插件后成为多租户的唯一模型出口。Gatehouse 自身不认识任何组织平台。

## 2. 用户与场景

- 个人用户：多把自己的 API key，想按任务类型自动选模型与思考强度，并在发给外部厂商前脱敏。本机 `127.0.0.1` 运行，Alcove 的 provider 端点指过来。
- 组织运维：全组织的模型调用走一个出口；按部门预算、数据分级硬约束路由；审计只见脱敏后内容。
- 插件开发者（首期只有第一方）：接鉴权/策略、审计、脱敏检测器、提供方适配、钩子。

## 3. 范围

首期内：

1. OpenAI 兼容入口：`/v1/chat/completions`、`/v1/models`；支持工具调用、图像输入透传、流式与非流式（流式仅在无脱敏或本地目标时透传；外部目标整条缓冲）。
2. 提供方适配：OpenAI 兼容出站（含 DeepSeek、各家兼容端点、本地 vLLM/Ollama）。只做这一种协议。
3. 路由组：`order`（按序故障转移）、`usage`（按用量分摊）；组可嵌套一层。
4. 意图路由：规则按序匹配，条件含 token 长度、是否带图、是否请求推理、来源标签、意图文字（小模型分类，8 s 超时）、时间段；命中指定模型与 `useEffort`；同一回合决策固定。规则是偏好，数据分级是硬约束。
5. 脱敏层（见架构文档 5.3）：规则检测器包、组织/个人词典、Never-mask、模式 off/audit/mask/warn/block、按用户键控哈希占位符、会话 Vault、响应与工具参数回填、fail-closed、整条缓冲、审计只记类别计数。NER 为可选模块，进不进首期看验证周。
6. 令牌：网关令牌签发与校验（短时效、限路由组/模型/token 上限/数据分级），个人模式一把本机令牌即可。
7. 计量：按令牌归因的 token 与成本、按天汇总、OTLP 导出；个人模式本地 SQLite 报表。
8. 插件接口 v1：子进程 + RPC（hashicorp/go-plugin 模式），五类扩展点：鉴权/策略（令牌校验、用户与部门与数据分级解析、允许的路由组与自带 API 判定）、审计接收、脱敏检测器、提供方适配、请求/响应钩子。
9. 两种运行模式：`personal`（单二进制、单配置文件、本机监听、无多租户）与 `org`（多租户，由策略插件提供租户上下文）。
10. 管理：CLI（`gatehouse serve|token issue|config check|redact try`）；`org` 模式的管理 API 供 Cloister 控制台调用。

首期外：Anthropic/Gemini 协议互转、订阅账号复用、桌面 GUI、Bun 中间件、流式下的实时脱敏、多层嵌套路由组、`smart/rotate/pace` 组。

## 4. 功能需求

- F1 任一请求的决策路径可解释：响应头或审计记录给出命中的规则、路由组、最终模型、脱敏模式与类别计数。
- F2 数据分级硬约束：`confidential` 请求的候选只在本地组；若候选全部不可用，拒绝而不是降级到外部。
- F3 脱敏回填覆盖响应文本、`tool_calls.arguments`、thinking 文本；同一用户同一值跨回合同一占位符。
- F4 fail-closed：策略要求脱敏而检测器或 NER 不可用 → 503，不放行；NER 超时只跑规则不算失败。
- F5 自带 API：用户在组织内登记的 key 只存网关密钥库，调用时按策略判定允许后使用，脱敏同样生效。
- F6 令牌过期或越权（请求的模型不在令牌范围）→ 401/403，审计记录。
- F7 个人模式零配置启动：`gatehouse serve` 读 `~/.gatehouse/config.yaml`，没有则生成样例并退出说明。

## 5. 非功能需求

- 单二进制，Windows/Linux/macOS 交叉编译，无运行时依赖；个人模式空闲 RSS ≤ 40 MB。
- 网关自身延迟（不含模型）：无脱敏 p95 ≤ 5 ms；规则脱敏 2k token p95 ≤ 30 ms；NER 另计。
- 明文只存在于 Vault 与出站前内存；日志、计量、钩子只见脱敏后内容；Vault 可选落盘加密。
- 密钥库：个人模式用 OS 钥匙串；org 模式用加密文件或外部 KMS 接口（插件）。

## 6. 依赖与接口

- 参考实现：magpie（路由组、意图路由、Privacy masking）；hashicorp/go-plugin（插件形态）。不嵌入任何一个。
- 对 Alcove：OpenAI 兼容端点；个人模式下 Alcove 把 provider 指向 `http://127.0.0.1:<port>/v1`。
- 对 Cloister：通过 `gatehouse-cloister` 插件（Dovetail 提供）接令牌校验、策略、审计；Gatehouse 不直接调用 Cloister API。

## 7. 验收标准（端到端）

脚本化、可重复，产出 `e2e/report/*.md`：

- G1 个人模式：两个假提供方（本地 HTTP 假服务）+ 一条意图规则；发闲聊 → 命中小模型；发长文请求 → 命中强模型；强模型假服务宕机 → `order` 组切到备用；报告列出每次决策。
- G2 脱敏：请求含手机号、身份证、客户词典词、订单号干扰项；抓外部假服务收到的请求体，断言占位符、订单号未被误脱；响应与工具参数回填为原值；审计只含类别计数；Never-mask 的值原样。
- G3 fail-closed：禁用检测器插件后发请求 → 503，外部假服务未收到任何请求。
- G4 令牌：签发限定模型 A 的令牌，请求模型 B → 403；过期 → 401。
- G5 org 模式：用一个假策略插件返回部门与 `confidential` 分级 → 路由只在本地组；本地组全部宕机 → 拒绝不降级。
- G6 计量：G1–G5 的用量按令牌汇总可在 CLI 报表与 OTLP 导出中核对一致。
