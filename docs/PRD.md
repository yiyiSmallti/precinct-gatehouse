# Gatehouse 首期 PRD

> **版本**：`0.1` · **对应架构文档**：`v0.18` · **范围**：首期（MVP）

---

## 1. 目标

构建一个独立可用的模型网关：对内对外统一使用 OpenAI 兼容 HTTP，将路由、脱敏、计量与短时效令牌整合为单一二进制。个人用户可将其作为本机网关使用；组织接入 `gatehouse-cloister` 插件后，即可作为多租户唯一模型出口。Gatehouse 自身不依赖或识别任何特定组织平台。

---

## 2. 用户与场景

| 角色 | 核心诉求 | 运行方式 |
| --- | --- | --- |
| **个人用户** | 管理多把自有 API Key，按任务类型自动选择模型与思考强度，并在发往外部厂商前完成脱敏 | 本机 `127.0.0.1` 运行，Alcove 的 provider 端点指向网关 |
| **组织运维** | 收拢全组织的模型调用出口，按部门预算与数据分级实施硬约束路由，确保审计仅见脱敏后内容 | 服务端部署，配合策略插件集中管控 |
| **插件开发者** | 接入鉴权/策略、审计接收、脱敏检测器、提供方适配及请求/响应钩子（首期面向第一方） | 通过 gRPC 插件接口扩展 |

---

## 3. 范围

### 3.1 首期内（In Scope）

1. **OpenAI 兼容入口**：`/v1/chat/completions`、`/v1/models`；支持工具调用、图像输入透传、流式与非流式（流式仅在无脱敏或本地目标时透传；外部目标整条缓冲）。
2. **提供方适配**：OpenAI 兼容出站（含 DeepSeek、各家兼容端点、本地 vLLM / Ollama）。首期仅实现这一种出站协议。
3. **路由组**：`order`（按序故障转移）、`usage`（按用量分摊）；路由组可嵌套一层。
4. **意图路由**：规则按序匹配，条件覆盖 token 长度、是否带图、是否请求推理、来源标签、意图文字（小模型分类，8 s 超时）、时间段；命中后指定模型与 `useEffort`，同一回合决策固定。规则属于偏好，数据分级属于硬约束。
5. **脱敏层**（见架构文档 5.3）：规则检测器包、组织/个人词典、Never-mask 白名单、`off / audit / mask / warn / block` 五种模式、按用户键控哈希占位符、会话 Vault、响应与工具参数回填、fail-closed、整条缓冲、审计只记类别计数。NER 为可选模块，是否纳入首期视验证周结论。
6. **令牌**：网关令牌签发与校验（短时效、限路由组 / 模型 / token 上限 / 数据分级），个人模式使用本机令牌即可。
7. **计量**：按令牌归因的 token 与成本统计、按天汇总、OTLP 导出；个人模式提供本地 SQLite 报表。
8. **插件接口 v1**：子进程 + RPC（`hashicorp/go-plugin` 模式），覆盖五类扩展点：鉴权/策略（令牌校验、用户/部门/数据分级解析、允许的路由组与自带 API 判定）、审计接收、脱敏检测器、提供方适配、请求/响应钩子。
9. **两种运行模式**：`personal`（单二进制、单配置文件、本机监听、无多租户）与 `org`（多租户，由策略插件提供租户上下文）。
10. **管理能力**：CLI（`gatehouse serve|token issue|config check|redact try`）；`org` 模式提供管理 API 供 Cloister 控制台调用。

### 3.2 首期外（Out of Scope）

Anthropic / Gemini 协议互转、订阅账号复用、桌面 GUI、Bun 中间件、流式下的实时脱敏、多层嵌套路由组、`smart / rotate / pace` 路由组。

## 4. 功能需求

| 编号 | 需求描述 |
| --- | --- |
| **F1** | **决策路径可解释**：任一请求的响应头或审计记录须给出命中的规则、路由组、最终模型、脱敏模式与类别计数。 |
| **F2** | **数据分级硬约束**：`confidential` 请求的候选仅限本地组；若本地候选全部不可用，直接拒绝，不得降级到外部。 |
| **F3** | **全量脱敏回填**：回填覆盖响应文本、`tool_calls.arguments`、`thinking` 文本；同一用户同一敏感值跨回合保持同一占位符。 |
| **F4** | **Fail-Closed**：策略要求脱敏但检测器或 NER 不可用时返回 `503`，拒绝放行；NER 超时仅退化为跑规则，不算失败。 |
| **F5** | **自带 API（BYO API）**：用户在组织内登记的密钥仅存网关密钥库，调用时按策略判定允许后使用，脱敏同样生效。 |
| **F6** | **令牌鉴权与越权拦截**：令牌过期或请求模型不在允许范围内时返回 `401 / 403`，并写入审计记录。 |
| **F7** | **个人模式零配置启动**：`gatehouse serve` 读取 `~/.gatehouse/config.yaml`，若不存在则生成样例并提示说明。 |

---

## 5. 非功能需求

- **交付与资源占用**：单二进制，支持 Windows / Linux / macOS 交叉编译，无运行时依赖；个人模式空闲 RSS ≤ 40 MB。
- **网关自身延迟（不含模型耗时）**：无脱敏 p95 ≤ 5 ms；规则脱敏 2k token p95 ≤ 30 ms；NER 另计。
- **数据安全**：明文仅存在于 Vault 与出站前内存；日志、计量、钩子仅见脱敏后内容；Vault 可选落盘加密。
- **密钥库**：个人模式使用 OS 钥匙串；`org` 模式使用加密文件或外部 KMS 插件接口。

---

## 6. 依赖与接口

- **参考实现**：magpie（路由组、意图路由、Privacy masking）；`hashicorp/go-plugin`（插件形态）。不直接嵌入其中任何代码。
- **对 Alcove**：暴露 OpenAI 兼容端点；个人模式下 Alcove 将 provider 指向 `http://127.0.0.1:<port>/v1`。
- **对 Cloister**：通过 `gatehouse-cloister` 插件（由 Dovetail 提供）对接令牌校验、策略与审计；Gatehouse 不直接调用 Cloister API。

## 7. 验收标准（端到端）

端到端测试须脚本化、可重复执行，并产出报告至 `e2e/report/*.md`：

| 用例 | 验证目标与断言 |
| --- | --- |
| **G1 个人模式路由** | 两个本地假提供方 + 一条意图规则；闲聊命中小模型、长文命中强模型；强模型宕机时 `order` 组自动切至备用；报告列出每次决策。 |
| **G2 脱敏与回填** | 请求含手机号、身份证、词典词及订单号干扰项；校验外部假服务收到的请求体含占位符且订单号未被误脱；响应与工具参数正确回填；审计仅含类别计数；Never-mask 原样保留。 |
| **G3 Fail-Closed** | 禁用检测器插件后发请求，返回 `503` 且外部假服务未收到任何请求。 |
| **G4 令牌范围与过期** | 签发限定模型 A 的令牌，请求模型 B 返回 `403`；令牌过期返回 `401`。 |
| **G5 `org` 模式硬约束** | 使用假策略插件返回部门与 `confidential` 分级，验证路由仅限本地组；本地组全部宕机时拒绝且不降级。 |
| **G6 计量一致性** | 核对 G1–G5 按令牌汇总的用量在 CLI 报表与 OTLP 导出中完全一致。 |
